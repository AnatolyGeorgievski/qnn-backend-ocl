# DEBUG-ONE: отладка только `mul_mat`

## Правило METHOD

> **Один метод за ход.**

За один сеанс отладки трогаем ровно один метод.
Для `mul_mat` это значит:

```bash
export QNN_DBG=mul_mat
```

Ничего другого в `QNN_DBG` не ставим — иначе лог засорится
и нарушим правило «один метод за ход».

## Что печатает stub

При `QNN_DBG=mul_mat` в stderr пойдёт:

```
[qnn_dbg mul_mat] enter: m=4096 n=11008 k=4096 ne=45056000 type=0
[qnn_dbg mul_mat] branch: cublas (fallback fp32/fp16)
[qnn_dbg mul_mat] leave: cublas done
```

Три уровня:

| Строка | Когда | Зачем |
|--------|-------|-------|
| `enter` | в начале `qnn_cuda_mul_mat` | размеры, тип — сверить с ожидаемым |
| `branch` | в начале выбранной ветки | убедиться, что диспетчер ушёл в нужную ветку |
| `leave` | в конце ветки, перед `return` | убедиться, что ветка завершилась |

## Как читать лог

1. **Нет `enter`** — функция не вызывается. Искать выше по стеку.
2. **`enter` есть, `branch` нет** — упали между enter и первой веткой
   (сейчас в stub это невозможно, но при добавлении кода — проверить).
3. **`branch` не та, что ждём** — условия веток в `mul_mat.cu` неверны.
4. **`branch` есть, `leave` нет** — ядро/вызов внутри ветки завис или упал.
   Смотрим `cuda-memcheck` / `compute-sanitizer`.
5. **`enter` + `branch` + `leave` все есть** — диспетчер работает,
   дальше отлаживаем само ядро (уже другой метод, другой ход).

```bash
#    найти условие if(0) и заменить на реальное.
```

## Следующий ход

Когда `mul_mat` стабильно печатает enter → branch → leave
и диспетчер уходит в нужную ветку — **закрываем ход**.
Следующий метод отлаживаем отдельным ходом:
`QNN_DBG=<next_method>`.
